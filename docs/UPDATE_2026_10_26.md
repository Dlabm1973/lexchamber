## Secretary access

An advocate with a connected, active practice can link up to five verified, registered secretary accounts under Team access. No invitation emails are sent. The secretary uses the advocate’s practice and subscription without receiving backend credentials. A matching grant in the advocate’s Clerk private metadata is checked on every request. Removing it revokes subsequent access, even if the secretary’s metadata still contains an old practice pointer.

Allowed: firms, matters, draft invoices, recording payments, viewing billing documents and sharing issued documents. Restricted: final invoice issue/amendment, reversals, credit notes/cancellation, archiving, banking/rates/VAT settings, expenses, financial reports, migration, subscription administration and team management. Secretary access includes invoice rates and banking details printed on client documents, but does not permit editing practice settings.

The existing backend continues to work through the authorising advocate’s identity. The updated signed Apps Script recognises the actual secretary for audit entries. Until that script is deployed, old backend audit entries identify the authorising advocate. Clerk authentication metadata and private practice connections remain outside the client spreadsheet; practice financial records remain in the client’s own backend.

## Existing backend upgrade

Do not create another Sheet or reset setup. Back up the existing Sheet, replace the code in its existing Apps Script project with client/Backend_Setup.txt, retain SPREADSHEET_ID / SHARED_SECRET / ALLOWED_EMAILS, and deploy a new version of the existing web app deployment. The URL stays the same. This enables adjacent-cell batch writes, reuses the spreadsheet handle within each request, avoids repeated reads during data refresh, adds named secretary audit entries and opening-balance imports. It does not change existing schema or overwrite existing records on deployment. Instructions are also available at /backend-guide.html#upgrade.

## Migration

The Migration workspace supplies CSV templates and checks relationships, duplicate source rows, destination matches and dates before writing. Firms and matters work with the existing backend. Opening balances require the updated script and an explicit matching source reconciliation total. They carry only unpaid balances, remain visible in debtors and are excluded from fees invoiced; they do not recreate tax invoices, VAT or historical payments. Imports commit row by row; confirmed rows remain on a later error. Refresh and preview the source again to reconcile remaining rows.
